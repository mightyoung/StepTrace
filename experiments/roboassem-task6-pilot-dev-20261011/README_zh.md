## 研究范围与身份约束

- 视频来源定位为 RoboAssem 官方 task 6 展示片 `task6_m_1.mp4`；视频只用于单条开发候选，不作为事件真值。
- 持续使用同一 `white_u_part` 物理身份；左右蓝座分别固定为 `blue_seat_left` 与 `blue_seat_right`。遮挡、姿态变化或画面歧义时保留 ID 并降低当前可判定性，不新建/交换身份。
- 观察过程候选为：可见分离 → 插入外观 → 夹爪放手后仍在位的可见保持。`insertion_appearance` 和 `apparent_hold_after_release` 仅是 RGB 可见描述，不能升级成内部锁紧、受力、牢固或扭矩结论。
- 用户提供的线索称最初左座插入没有展示。因此不得从这段视频判定完整 SOP 完成，也不得补写未见步骤。
- 事件的不确定时段以“最后一个可确认前态”到“首个可确认后态”界定；不制造精确物理接合时刻。来源画面、字幕和预测输出分别记录；字幕不能作为真值。

## 首轮对照设计

若媒体随后可读，且既有授权明确了可用模型、配置、次数与费用边界，首轮才可运行：

1. **F 单帧**：在冻结截止 PTS 的当前帧上回答可见关系和不确定项。
2. **HF 同前缀**：复用 F 的完全相同当前帧，最多加 3 张按 PTS 排序的真实历史帧；选择 2 或 3 张时记明每张帧的源索引和 PTS。
3. **H 诊断**：只用于检查 last-known 历史状态如何表达；不进入主要比较。

F 与 HF 共用相同的截止点、当前帧、分辨率和问题。保持历史事件与当前适用性分开；历史上曾插入不自动证明当前仍在位。这里不累计 91 张图、不运行 27 次调用，也不新开付费 API。当前模型调用数为 0；既有授权配置/费用尚未核定，未获核定前不运行。

## 帧与输入准备

媒体可读后，先核对准确字节数和 SHA，再用现有 ffprobe 记录视频流、time base、逐帧 PTS、源帧索引与 PTS 秒值。先人工筛出候选锚点，再固定截止点。每个事件至少列：末个可确认前态、首个可见变化候选、首个可确认后态、放手后首个仍在位候选、片尾状态；遇到身份或关系不明时标 `unknown`。

原始帧只读保存在研究数据目录；模型输入另存副本。若画面含叠加文字，模型输入只用不透明色块遮盖，保留未经处理原帧，并记录遮罩坐标、尺寸、文本类别、源 PTS 和派生 SHA；不做内容填补/重绘。关键帧清单需区分“源时间”“帧索引”“PTS”“视频时间”，不能仅用约 30 fps 换算帧号。
