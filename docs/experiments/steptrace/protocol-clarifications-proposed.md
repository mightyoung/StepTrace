# StepTrace：待冻结的协议澄清清单

本文是下一版本设计建议，不改变2026-10-10已冻结协议、检查结果或首答。

## 四处必须统一的说明

1. 继承起点：检查器要求from_source_pts等于所引用支持证据的最大终点。必须明确采用这一等式，还是允许其他有说明的起点；schema、文字和夹具保持一致
2. 计数字段：若visible_count仅适用于visible_occupancy，schema应明确约束其他证据kind只能为null；若也允许表达单部件连接数量，应拆分字段，避免占位数与连接数混用
3. 证据缺口：未采样区间不等于看到了遮挡。应区分sampling_gap与observed_occlusion，明确各自可以引用的证据，不能暗中要求前者也有occlusion记录
4. 作用范围：单个槽位或身份映射失效不应在未说明规则的情况下自动撤销整体占位继承。状态变化须标明影响的对象、槽位、记录ID与aggregate范围；两种范围分别核验

每条规则至少配一份应接受和一份应拒绝的逻辑夹具。逻辑夹具通过只能证明规则一致性，不能当真实视频效果。

## 继续保持的边界

- 最后直接观察、截止估计、历史确认和当前适用性分层
- 只用当前条件实际给定的帧；H不借用被隐藏的截止结局，F不补造历史
- 明确新分离/换物反证不得被旧状态覆盖；撤销记录保留，重新连接需重新确认
- 未观察变化不能标为已排除；未知不自动等于缺失
- 外部占位、外部连接与内部紧固分开；牢固及安全不从本类视觉证据推出
- 原始首答与失败保留；协议更新后新开一轮，不能回写旧答
- 真实拆卸、合成倒放、不同拓扑及同源派生物分别处理，遵守同源分组

## 下一小轮的最小状态更新检查

当前HF是单次完整上下文重述，不能代替持久状态测试。后续可对一个真实例与一个合成例分别冻结两阶段输入：阶段一仅给早期证据并保存记录ID；阶段二只新增截止反证，要求保留旧历史事实、明确撤销或暂停当前适用性。先补条件内参考、清楚的目标身份与接口证据，再执行该小轮；本建议尚未运行。
